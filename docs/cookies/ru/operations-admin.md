# Модуль cookie: использование и администрирование

- [К разделу cookie](./README.md)
- [К общему разделу документации](../README.md)

## Что это за документ

Документ описывает рабочий сценарий эксплуатации cookie-модуля:
- как включить модуль в проект;
- где в административной панели настраиваются категории, политика и баннер;
- какие разделы в административной панели только для просмотра;
- какие команды применять для первичной инициализации и обслуживания.

## Быстрый путь запуска

1. Подключите приложения и маршруты.
2. Выполните миграции.
3. Запустите начальную инициализацию коробочных данных.
4. Проверьте категории cookie и реестр интеграций.
5. Подготовьте и опубликуйте редакцию политики cookie.
6. Подготовьте и опубликуйте редакцию баннера cookie.
7. Подключите баннер в шаблон сайта.
8. Проверьте работу страницы настроек `/cookies/` и действий баннера `/cookies/banner/`.

## Подключение в проект

### Приложения

Убедитесь, что в `INSTALLED_APPS` есть:
- `django_cookies_152fz`;
- `django_consent_152fz` (если используется общий контур согласий и проверок настроек).

### Маршруты

Подключите маршруты cookie-модуля:

```python
from django.urls import include, path

urlpatterns = [
    path("", include("django_cookies_152fz.urls")),
]
```

Доступные маршруты:
- `/cookies/` — страница управления выбором категорий;
- `/cookies/banner/` — обработчик действий баннера.

### Шаблон

Подключите тег баннера в базовом шаблоне:

```django
{% load cookies_tags %}
...
{% render_cookie_banner %}
```

## Настройки в `settings.py`

Базовая конфигурация cookie-модуля задаётся в `DJANGO_152FZ_COOKIES`.

```python
DJANGO_152FZ_COOKIES = {
    "enable_cookies": True,
    "default_cookie_category_codes": ["necessary"],
    "cookie_banner": {
        "bootstrap_initial_revision": True,
        "preferences_page_template": "django_cookies_152fz/cookie_preferences.html",
        "banner_variant": "card",
        "consent_ui_variant": "panel",
        "reconsent_notice_variant": "inline",
        "text_preset": "ru_balanced",
    },
    "cookie_runtime": {
        "force_banner": False,
        "preview_param": "cookie_banner_preview",
        "custom_css_url": "",
        "custom_js_url": "",
        "hide_for_bots": True,
        "bot_patterns": [],
        "user_agent_mode": "all",
        "shared_subdomain": False,
        "site_domain": "",
        "cookie_domain": "",
        "geo_signal_hook": "",
    },
    "cookie_retention": {
        "batch_size": 500,
        "records_older_than_days": None,
        "events_older_than_days": None,
        "banner_states_older_than_days": None,
        "records_max_count": None,
        "events_max_count": None,
        "banner_states_max_count": None,
        "private_records_older_than_days": None,
        "private_events_older_than_days": None,
        "private_signal_paths": [],
        "protect_current_records": True,
    },
}
```

Где настраивать что:
- поведение показа и варианты баннера: `cookie_banner`;
- техническое поведение в запросе и домене: `cookie_runtime`;
- очистка и объёмы аудита: `cookie_retention`.

## Первичная инициализация

После миграций выполните:

```bash
python manage.py bootstrap_152fz_cookie_defaults
```

Команда создаёт:
- коробочные категории cookie;
- стартовую редакцию политики cookie;
- стартовую редакцию баннера cookie.

## Полная карта меню административной панели

Ниже перечислены все зарегистрированные сущности cookie-модуля.

### `Настройки админ-инструментов cookie`

Что это:
- единичная запись для технических настроек административной панели.

Что настраивается:
- `csv_export_delimiter` — разделитель CSV-экспорта.

Особенности:
- доступ только суперпользователю;
- удалить запись нельзя;
- добавить можно только одну запись.

### `Cookie-категории`

Что это:
- справочник категорий для группировки cookie и построения снимка в редакции политики.

Что настраивается:
- код, заголовок, описание;
- обязательность категории;
- порядок сортировки;
- активность.

Когда менять:
- при появлении новой категории обработки или изменении классификации.

### `Элементы cookie-реестра`

Что это:
- реестр технических интеграций (cookie и скриптов), которые завязаны на решение пользователя.

Что настраивается:
- код интеграции;
- категория;
- поставщик;
- назначение;
- срок хранения;
- стратегия очистки;
- источник (`src_url`);
- активность.

Когда менять:
- при подключении/отключении внешних систем и аналитики.

### `Текстовые пресеты cookie-policy`

Что это:
- шаблоны текста политики cookie.

Что настраивается:
- код и заголовок пресета;
- текст политики;
- признаки коробочного/пользовательского варианта;
- активность.

Действия:
- клонирование выбранных пресетов в пользовательские пресеты.

### `Редакции cookie-policy`

Что это:
- версионируемые редакции текста политики cookie, которые публикуются и становятся активными.

Что настраивается:
- формат и текст редакции;
- снимок категорий;
- признак активной редакции.

Действия:
- публикация выбранного коробочного варианта текста;
- создание пользовательского черновика из коробочного варианта;
- клонирование выбранных редакций в черновики.

Важно:
- при публикации новая активная редакция отключает прошлую;
- реестр синхронизируется в снимок редакции;
- предыдущие актуальные согласия переводятся в устаревшие.

### `Текстовые пресеты cookie-баннера`

Что это:
- шаблоны текстов баннера cookie.

Что настраивается:
- заголовки, подписи, тексты кнопок, тексты для режима без JavaScript;
- признаки коробочного/пользовательского варианта;
- активность.

Действия:
- клонирование выбранных пресетов в пользовательские пресеты.

### `Редакции cookie-баннера`

Что это:
- версионируемые редакции баннера cookie (тексты, варианты показа и визуальные параметры).

Где какие настройки:
- блок `Тексты`: все пользовательские подписи баннера;
- блок `Варианты отображения`: вариант баннера, вид интерфейса выбора, вариант уведомления;
- блок `Визуальная настройка`: цветовые и визуальные параметры;
- блок `Видимость и кнопка закрытия`: поведение показа, закрытия, блокирующего режима и мобильные переопределения;
- блок `Устаревшие поля совместимости`: поля обратной совместимости.

Действия:
- клонирование выбранных редакций баннера в пользовательские черновики.

Важно:
- у коробочных редакций защищённые текстовые поля доступны только для чтения;
- при публикации новая активная редакция отключает прошлую.

### `Элементы реестра редакции cookie-policy`

Что это:
- снимок реестра интеграций на момент конкретной редакции политики.

Режим:
- только просмотр, без редактирования.

Назначение:
- аудит соответствия опубликованной политики и состава интеграций.

### `Записи cookie-согласий`

Что это:
- итоговое состояние выбора категорий по субъекту.

Режим:
- только просмотр.

Назначение:
- контроль текущего/устаревшего статуса;
- поиск по пользователю, анонимному токену, идентификатору запроса.

### `События cookie-согласий`

Что это:
- журнал событий по согласию (принятие, обновление, устаревание и связанные действия).

Режим:
- только просмотр.

Действия:
- экспорт выбранных событий в CSV.

### `Состояния cookie-баннера`

Что это:
- серверное состояние жизненного цикла баннера по субъекту.

Режим:
- только просмотр.

Назначение:
- диагностика повторного показа, закрытия, выбранного действия и блокирующего режима.

## Где настраивать по задачам

### Нужно изменить текст политики cookie

1. Откройте `Текстовые пресеты cookie-policy` и подготовьте вариант.
2. В `Редакции cookie-policy` создайте редакцию (или черновик из пресета).
3. Опубликуйте редакцию как активную.

### Нужно изменить внешний вид/поведение баннера

1. Откройте `Текстовые пресеты cookie-баннера` и скорректируйте тексты.
2. Откройте `Редакции cookie-баннера`.
3. Настройте блоки `Варианты отображения`, `Визуальная настройка`, `Видимость и кнопка закрытия`.
4. Опубликуйте редакцию.

### Нужно добавить новую интеграцию (скрипт/cookie)

1. Добавьте или актуализируйте категорию в `Cookie-категории` (если требуется).
2. Добавьте запись в `Элементы cookie-реестра`.
3. Проверьте, что в активной `Редакции cookie-policy` отражён актуальный снимок.

### Нужно выгрузить события в CSV

1. Откройте `События cookie-согласий`.
2. Выберите записи.
3. Примените действие `Экспортировать выбранные события в CSV`.
4. При необходимости заранее задайте разделитель в `Настройки админ-инструментов cookie`.

### Нужно очистить старые записи аудита

Запустите:

```bash
python manage.py cleanup_152fz_cookie_audit --dry-run
python manage.py cleanup_152fz_cookie_audit
```

Параметры очистки задаются в `DJANGO_152FZ_COOKIES["cookie_retention"]`.

## Практика из демо-сайта

Ниже зафиксированы решения, которые показали стабильное поведение в демо-сайте и подходят как рабочий шаблон внедрения.

### Встраивание баннера

- баннер подключается один раз в базовом шаблоне сайта через `{% render_cookie_banner %}`;
- это покрывает все публичные страницы без дублирования разметки по шаблонам;
- отдельная ссылка в верхнем меню на страницу cookie-настроек не обязательна, если включена кнопка повторного открытия баннера.

### Маршруты

- основной набор маршрутов проекта подключается отдельно от cookie-маршрутов;
- для cookie-модуля используется отдельный префикс `/cookies/`;
- это упрощает диагностику и снижает риск пересечения имён маршрутов.

### Рабочий профиль настроек

Для публичного сайта в демо стабильно использовалась схема:
- `cookie_banner.show_launcher=True`;
- `cookie_banner.show_preferences_link=False`;
- `cookie_runtime.hide_for_bots=True`;
- `cookie_runtime.preview_param="cookie_banner_preview"`;
- явный список шаблонов роботов в `cookie_runtime.bot_patterns`.

Смысл схемы:
- пользователь всегда может повторно открыть баннер кнопкой;
- лишние точки входа на страницу настроек не перегружают интерфейс;
- для поисковых роботов баннер не мешает обходу страниц;
- режим предпросмотра баннера доступен вручную через параметр URL.

### Инициализация данных

- после миграций запускается `bootstrap_152fz_cookie_defaults`;
- для демонстрационного стенда допустима автоматизация этого шага через `post_migrate`;
- для рабочего окружения лучше использовать явный запуск команды в сценарии развёртывания, чтобы избежать неявных изменений данных.

### Проверки после изменений

После каждого изменения cookie-настроек в демо обязательно перепроверялись:
- отображение баннера и страницы `/cookies/` на русском и английском;
- сохранение выбора категорий;
- повторное изменение выбора;
- отсутствие ошибок в браузерной консоли и в журнале сервера;
- отсутствие регрессий в базовом сайте (публичные страницы, формы, вход, административная панель).

Отдельный чеклист из демо: `demo/notes/smoke-checklist.md`.

## Инвентаризация интеграций

Для рекомендательной проверки соответствия реестра категориям:

```bash
python manage.py inventory_152fz_cookie_integrations
```

Это вспомогательный отчёт. Решение о классификации принимает оператор.

#### CSV delimiter behavior for event export

- `Cookie consent events` export uses `csv_export_delimiter` from `Cookie admin settings`.
- Allowed delimiters: `,`, `;`, `TAB` (`\t`), `|`.
- Invalid values safely fall back to `,`.
