# Модуль cookie: миграция

- [К разделу cookie](./README.md)
- [К общему индексу документации](../README.md)

## Назначение

Документ фиксирует путь обновления для отдельного cookie-пакета `django_cookies_152fz`.

## Сброс базовой линии

Историческая цепочка cookie-миграций (`0002+`) сведена в единый файл
`django_cookies_152fz/migrations/0001_initial.py`.

Это упрощает структуру пакета, но для существующих установок требует
контролируемого перехода по миграциям.

## Текущий контракт миграций и моделей

- канонический пакет приложения: `django_cookies_152fz`;
- стабильная метка приложения в графе миграций и БД:
  `django_consent_152fz_cookies`;
- имена таблиц и ссылки на исторические модели не меняются;
- cookie-миграции могут применяться в `cookies-only` без обязательной
  зависимости от `django_consent_152fz`.

## Путь обновления для существующих установок

1. Обновить зависимости до совместимых версий `django-consent-152fz` и `django-cookies-152fz`.
2. Использовать в `INSTALLED_APPS` канонический путь `django_cookies_152fz`.
3. Удалить старый путь приложения из `INSTALLED_APPS`, если он был указан.
4. Оставить нужный маршрут:
   - `django_consent_152fz.urls` для полного сценария;
   - `django_consent_152fz.cookies.urls` для `cookies-only` маршрутизации.
5. Выполнить `python manage.py migrate`.
6. Проверить маршруты cookie, состояние баннера и существующие cookie-записи.

## Переходная совместимость

Поддерживаются:
- старые импорты `django_consent_152fz.cookies.*`;
- старые пути шаблонов в пространстве `django_consent_152fz/templates/...`
  через переходный слой в `django_cookies_152fz`.

## Несовместимые сценарии после снятия переходного слоя

- прямое использование `django_consent_152fz.cookies.*` как канонических импортов;
- ожидание, что шаблоны и статические ресурсы cookie останутся в пространстве
  `consent` без слоя совместимости.

## Новая установка и обновление

- новая установка: использовать `django_cookies_152fz` в `INSTALLED_APPS` для `cookies-only`;
- обновление существующей установки: переходные импорты допустимы временно,
  но путь приложения должен быть каноническим.

## Известные ограничения

- в смешанных средах нужен отдельный план очистки старых импортов до удаления
  переходного слоя;
- в пользовательских миграциях с прямыми ссылками на старые python-пути
  нужно перейти на ссылки через метку приложения и имя модели.

## Снятие переходной совместимости

- сначала переходные импорты поддерживаются как временная мера;
- затем публикуются предупреждения о прекращении поддержки старых путей;
- после стабилизации линейки удаляются переходные алиасы.

Условие удаления: минимум один стабильный цикл выпуска без регрессий в
`cookies-only`, `consent-only` и совместной установке.

## Контроль после обновления

- проверить сценарии из [./testing.md](./testing.md);
- проверить интеграционный набор из каталога `tests`.
