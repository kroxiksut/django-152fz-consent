# Модуль согласий: ключевые инварианты

- [К разделу согласий](./README.md)
- [К общему разделу документации](../README.md)

## Доменные инварианты

- каждое согласие привязывается к конкретной `DocumentRevision`;
- поток согласия рассматривается как пара `purpose_code + document_code`;
- история хранится в неизменяемых аудиторских событиях;
- статус `outdated` возникает при изменении релевантной редакции документа или политик.

## Инварианты субъекта

- поддерживаются авторизованные и анонимные субъекты;
- анонимные согласия могут быть привязаны к пользователю после входа;
- анонимный отзыв управляется отдельной политикой и не включается неявно.

## Транспортные инварианты

- представления, шаблонные теги и API остаются тонким адаптерным слоем над сервисами;
- внешним интеграциям не рекомендуется прямой импорт внутренних модулей `core.services`;
- стабильный контракт для интеграций проходит через `service_api`.

## Инварианты области применения

- необязательные дополнения не должны становиться обязательными для сценариев ядра;
- экспериментальный контур подтверждения не заменяет ядро и не формирует отдельный домен согласий.
