# Политика безопасности

[English version](./SECURITY.md)

В репозитории поставляются два независимо версионируемых пакета — `django-consent-152fz`
(жизненный цикл согласий на обработку персональных данных) и `django-cookies-152fz`
(баннер и исполнение cookie). Оба работают с **персональными данными** в контексте
152-ФЗ, включая неизменяемый журнал аудита. Пожалуйста, относитесь к вопросам
безопасности соответствующе.

## Поддерживаемые версии

Пакеты версионируются независимо друг от друга; всегда обновляйтесь до последнего
релиза каждого. Исправления безопасности выпускаются только для последней
опубликованной версии и ветки `main`.

| Пакет | Версия | Поддержка |
| --- | --- | --- |
| `django-consent-152fz` | последняя `0.1.x` | ✅ |
| `django-cookies-152fz` | последняя `0.1.x` | ✅ |
| любой | более старые / pre-release сборки | ❌ |

> Проект находится в стадии **alpha** (`0.1.0`). API и контракты могут меняться;
> обновляйтесь оперативно при выходе релиза с исправлением безопасности.

## Как сообщить об уязвимости

**Пожалуйста, не создавайте публичных GitHub issue, pull request или discussion по
вопросам безопасности** — публичное раскрытие до выхода исправления создаёт риск для
субъектов персональных данных.

Сообщайте приватно через GitHub:

1. Откройте репозиторий
   [github.com/kroxiksut/django-152fz-consent](https://github.com/kroxiksut/django-152fz-consent).
2. Вкладка **Security** → **Report a vulnerability** (приватный канал GitHub для
   сообщений об уязвимостях).

Если приватный канал вам недоступен, свяжитесь с мейнтейнером приватно через GitHub,
не создавая публичный issue.

### Что приложить

- затронутый пакет и версия (`django-consent-152fz` и/или `django-cookies-152fz`);
- затронутый модуль/путь и, по возможности, конкретное место в коде;
- минимальный воспроизводимый пример или proof of concept;
- наблюдаемое воздействие (утечка данных, нарушение целостности журнала аудита,
  повышение привилегий и т. п.);
- предлагаемое исправление, если есть.

**Не включайте** в отчёт реальные персональные данные (ПДн) — используйте
синтетические.

### Чего ожидать

- подтверждение получения отчёта, как только мейнтейнер сможет его разобрать;
- оценку серьёзности и затронутых версий;
- скоординированное исправление и релиз с последующим публичным раскрытием
  (GitHub Security Advisory) после выхода исправления;
- упоминание автора отчёта по запросу.

Это open-source проект, сопровождаемый на условиях best-effort; сроки реакции
не гарантируются контрактно.

## Модель безопасности и границы доверия

Ряд механизмов безопасен **только при развёртывании согласно документации**.
Неправильная конфигурация здесь — наиболее вероятный источник реальных проблем,
поэтому такие места перечислены явно:

- **Авторинг HTML-ревизий — только для доверенных ролей.** Тела ревизий юридических
  документов и баннера, написанные в HTML, рендерятся без санитизации. Ограничьте
  авторинг HTML-ревизий доверенным персоналом. См. документы по авторингу и
  конфигурации модуля согласий.
- **IP клиента / `X-Forwarded-For`.** В журнале аудита фиксируется IP клиента. Доверяйте
  заголовку `X-Forwarded-For` только за корректно настроенным доверенным прокси —
  иначе IP в неизменяемом аудите можно подделать через заголовок. Настройте параметры
  доверенного прокси соответствующим образом.
- **Анонимный токен согласия — это bearer-секрет.** Он передаётся как cookie с флагами
  `Secure`, `HttpOnly`, `SameSite=Lax` и никогда не принимается из query-параметров.
  Обслуживайте сайт по HTTPS и не логируйте токен.
- **Неизменяемый журнал аудита.** События согласий/cookie работают только на добавление
  и по проекту защищены от удаления (в том числе bulk-delete и retention). Не обходите
  иммутабельные менеджеры; retention иммутабельных моделей требует реального
  архив-стока.
- **CSV-экспорты в админке** защищены от formula-injection; поля, контролируемые
  субъектом, нейтрализуются при экспорте.
- **Исполнение cookie-скриптов** использует позитивный allow-list источников скриптов,
  а не blocklist.

Полный набор проверенных аудитом мер и инвариантов см. в документации модулей:
согласия (`docs/consent/ru/`) и cookie (`docs/cookies/ru/`), в частности страницы
`invariants`, `configuration` и `operations-admin`.

## Область действия

В области: уязвимости в исходном коде пакетов под `src/`, затрагивающие
конфиденциальность, целостность или доступность данных согласий/cookie, журнала
аудита или поверхности admin/API.

Вне области: проблемы, требующие уже скомпрометированной доверенной роли (например,
вредоносный HTML, написанный доверенной учётной записью персонала, — это
задокументированная граница доверия, а не уязвимость), уязвимости в сторонних
зависимостях (сообщайте о них upstream) и находки, применимые только к развёртываниям,
сконфигурированным вопреки документации.
